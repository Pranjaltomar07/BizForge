# BizForge - Telecom Customer Churn Prediction

[![tests](https://github.com/YOUR-USERNAME/bizforge/actions/workflows/ci.yml/badge.svg)](https://github.com/Pranjaltomar07/bizforge/actions)

*Telecom churn prediction with calibrated probabilities and a retention-campaign value analysis.*

I wanted to see how far a churn model can go, and what it is worth to a business. This project uses real data (the IBM Telco Customer Churn sample, 7,043 customers). It goes from SQL tables to a model comparison, calibrated probabilities, an expected-value retention analysis and a Streamlit dashboard.

| | |
|---|---|
| Test ROC-AUC (held-out 20%) | **0.847** (95% bootstrap CI 0.825-0.868) |
| PR-AUC | 0.668 (random baseline 0.265) |
| Brier score | 0.134 (predict-the-base-rate baseline 0.195) |
| Top-10% risk lift | 2.9x |

My write-up of the results, caveats and next steps is in [FINDINGS.md](FINDINGS.md).

## Run
```bash
pip install -r requirements.txt
python run_all.py            # download data -> SQL ETL -> train/evaluate -> campaign analysis
streamlit run app.py         # dashboard
pytest -q tests              # offline tests (use a generated fixture, no download needed)
docker build -t bizforge . && docker run -p 8501:8501 bizforge
```

## Pipeline
| Stage | Files |
|---|---|
| Ingest | `src/download.py` (public IBM sample CSV; not redistributed here) |
| Transform | `src/etl.py` + `sql/stg_customers.sql`, `mart_features.sql`, `mart_churn_segments.sql` (SQLite; portable to Postgres with date/cast tweaks) |
| Model | `src/train.py`: majority baseline vs logistic regression vs random forest vs XGBoost via 5-fold CV on train; winner calibrated (isotonic) and scored once on the test set; bootstrap CI; permutation importance |
| Decision analysis | `src/profit.py`: expected net value of contacting the top-k riskiest customers, with a sensitivity grid |
| Serve | `app.py` |

## Method notes
- Model selection uses only the training split; the test split is touched once.
- `gender` is excluded from features by design. `customerID` and the label are excluded (tested).
- The retention-campaign numbers use an assumed save rate, cost and horizon. They are a scenario analysis, not measured uplift. Measuring uplift would need a randomized holdout.
